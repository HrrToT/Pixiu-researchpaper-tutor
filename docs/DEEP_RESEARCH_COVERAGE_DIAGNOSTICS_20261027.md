# 绑定具体目标的完整性缺口诊断

针对 D1-v36 最终覆盖只有 partial 标签、没有具体缺失内容和理由的问题，新运行使用 `.311`、`coverageDiagnosticsContractVersion=1`。本轮不追加真实模型案例，不给历史 partial 补写理由或升级判定。

## 行为

既有一次完整性核查要求每个 partial/missing 义务额外给出 `gapDetail`：未完成的 criterionIds、aspectIds，以及具体 `missingContent` 和 `reason`。目标列表必须恰好对应该义务实际未完成的子项，不接受遗漏、重复、跨义务目标或额外字段；每个文字字段非空且不超过 800 字。covered/not_required 不能夹带缺口诊断。

先执行既有事实和覆盖绑定检查，再校验诊断，避免总状态原为 covered、子项却 missing 的矛盾响应绕过要求。缺失或矛盾的诊断属于 invalid_response，不冒充有明确结论的内容缺口，也不会触发额外重试或自动认可正文。

有效诊断保存在审计和缺口记录中，并以“未核实的完整性诊断”标签传给既有修订流程。原问题、冻结要求和自身引用继续约束修订，诊断不是原文证据或新增用户要求。缺口的简短展示标签保留，不把私有诊断塞入默认正文。

新策略由服务端设定且不可修改，初始及修订后的覆盖核查都使用同一策略。旧研究没有新开关时，请求与结果保持原规则；没有增加模型轮次、输出 Token 上限、总预算或自动重试。

## 容量与实际回放

审查发现最初直接附加诊断规则会使通用容量裁剪去掉三条已引用证据的上下文，因此该候选没有提交。最终版本先保留所有已引用证据的完整 quote 和按原句子窗口得到的上下文，再以剩余容量选择完整的补查记录，不再为诊断移除已引用上下文。必需记录缺失时在发送前标记无效，重复身份继续由原有别名编码器在发送前拒绝；放不下时在发送前留下容量缺口。旧路径保持。

保存的 D1-v36 只读回放：旧请求和返回逐字段完全相同；旧请求 23,998 字节、15 条证据，新的请求 23,921 字节、11 条完整证据。四条自身引用的 quote 和准备好的上下文均与旧请求精确一致。其余未引用证据按剩余容量选择，不声称全部候选进入了请求。

旧响应不包含诊断，新协议明确拒绝，原 partial 保持，未删除字段或依据正面内容升级。生产写入和模型调用均为 0，原始 payload 哈希不变。回放证据见 `deep-research-evidence/coverage-diagnostics-replay-20261027.json`。
