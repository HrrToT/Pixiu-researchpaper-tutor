# 研究成果编辑与来源保护修复

保存用户编辑稿时，浏览器可以提交 `edited=false` 并清空版本列表，导致后续结果同步将它当作未修改报告替换。仅修改标题也未必产生保护标记。另外，新建成果只提交 `sourceResearchId` 别名时会绕过关联清理，已有旧格式研究关联也能被浏览器改写；服务端原本没有的来源字段可以被插入。

## 修复行为

- 已有研究成果的来源字段以服务端保存值为准；服务端没有该字段时，移除客户端插入值。
- 同时识别 `sourceRunId` 和旧格式 `sourceResearchId`，保留已有真实关联，拒绝浏览器重绑定。
- 新建用户成果无法仅通过别名或版本号制造研究关联；用户正文保持可保存。
- 服务端已知编辑过的成果再次保存时仍标记为已编辑；正文或标题变化同样产生保护标记。清除浏览器标记不再使它具备被新版报告自动替换的条件。
- 原始机器报告保持既有不可修改和不可被整份任务保存删除的规则。

## 验证

4 项新增 HTTP/服务集成回归在修复前全部失败，修复后通过。已有研究发布用例补上浏览器再次保存时清除标记的步骤，确认后续发布仍保存新版机器报告及旧版机器报告，并保留用户修改稿。

修复后 5 个关联测试类 91 项通过；最终全部 Java 回归 18 类 168 项通过，0 失败、0 错误、0 跳过，离线打包成功。测试使用内存 H2 和明确的研究响应夹具，没有真实模型调用。

使用新构建 JAR 再运行真实工作台与独立 Java/H2 的笔记持久化案例，1 项浏览器用例通过；编辑、清缓存刷新、历史恢复、过期修订号 409 保护、服务重启后的完整 JSON 保持均通过。新构建 SHA-256 为 `3172bd62c53081536f8d57288ea4accd587303226b15ae028b667e58f655a4aa`。
