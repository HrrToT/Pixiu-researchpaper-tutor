# 机制推理使用独立正文分支（.428）

AD1N-v15的边界解释被生成为“已报告设置＋比较证据不足”，包含英文方法名、初始化和衰减率清单。这类表达适合回答实际比较的证据范围，却不能自然解释一个局部机制能推出什么。它还占用了固定正文预算，使新手核心解释被压缩为术语和公式。此前模板只明确展示prose和boundary两个分支，是需要改进的表达限制；不能据此断定它是全部内容问题的唯一原因。

新任务将不可变 `authoredBodyContractVersion` 从1设为2。在完整事实生成配置中增加第三个互斥分支：

```json
{"kind":"inference","body":{"reasoning":{
  "premise":"本条原引用支持的具体机制",
  "consequence":"由此前提作出的局部推理及必要条件或范围"
}}}
```

两段均为非空中文正文，服务器只用换行连接，保留完整内容、主张ID、类型、问题归属及原引用权限，不添加结论、删句或授予事实认可。完整文本继续计入原字数预算，经过原事实、数值、范围和全答案完整性检查。私有reasonedBodies审计保留原始分支及unchecked标记，不能当作通过证据。

这不是为比较/泛化结论提供绕行路径。实际比较证据或泛化边界继续使用body.boundary及原算子审计；局部机制推理不能把用户的禁止性要求当原文前提，也不能推出作者从未保证、测试或证明某事。正常reported说明可继续用body.prose，不强制所有回答增加推理。模型选错类型仍可能失败，本分支不证明语义有效。

冲突的多个分支、顶层另一版正文、错误类型、空字段及额外隐藏结论均隔离为无效草稿，不从中挑一个版本发布。版本1保持原提示与编译行为。新版仅扩展初始生成；收到的旧请求不迁移，修订和压缩继续已有规范正文/边界协议及独立检查。
