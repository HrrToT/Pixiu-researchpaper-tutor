# 前置研究决策与完整工作流的职责分离

状态：下一版本实现约束，尚未实现或启用。目标仍为完整 DR0—DR5。

## 当前证据

E1-v48 在关闭推理时返回完整但结构错误的 JSON；E1-v49 开启低档推理后耗尽原 6144 输出上限，正文为零。两者均未到生命周期单元。实际输入存在重新提取差异，不能据此做档位效果的严格因果比较。

当前 graph.py 先要求私有计划生成状态清单与分阶段预算，再要求工作流元信息和各初始化单元重新选择全部状态。前置阶段因此同时承担研究决策与大量执行状态表达。下一版本分开这两项责任，最终成果要求不变。

## 新建运行的规划契约

- 使用独立、不可变、服务端创建的契约标记和持久化版本；旧运行、已失败响应、未知请求及原始身份不迁移、不重发。
- 前置响应保持 `sourceRefs, protocol, unresolved` 三个根字段。`protocol` 六个非空字符串分别为 `intervention, data, state, poseError, measurement, pairingBudget`。
- 该阶段选择可检验问题、比较目的、场景和训练内窗口选择、方法及组件职责、观测与配对判读、有限的阶段预算意图。`state` 描述组件与输入职责，完整张量形状和初值由后续工作流单元生成一次；不得编造已有资产或把缺失设置写成已实现事实。
- 使用单独的节点和原始响应日志，低嵌套的语法约束；关闭推理、2048 输出 Token、8192 响应字节、60秒单请求上限，仍受原整轮预算限制。这是待实现的角色分配，不是质量保证。
- 保留全部获准原文输入及来源身份；如输入超限，保存完整失败输入并停止。不得通过剪掉必要原文、组件、步骤或状态换取通过。

## 保持最终完整性

1. 生命周期元信息仍选择明确阶段、创建/释放时点、作用域、状态读写及输出。
2. 基线与各组件单元继续生成完整实际初值、输入选择、形状、数据类型、分布和变换；不由服务端填默认科学值，不接受 opaque weights 或未知维度占位符。
3. 完整组装后继续核对全部依赖、组覆盖、逐帧预算、评估与记录数据流；没有对应正式配置的概念选择不得当作完整方案。
4. 公开正文仍包含完整数据选择、控制、预算、步骤、测量、假设、判读和边界；事实与原文证据分开核验。前置决策只是未核验上下文，不提供来源权限或科学批准。
5. 不增加18次调用、10万Token、360秒整轮预算；不增加任何自动重试。新节点替代原前置规划请求，不与其重复调用。

## 接入与验收边界

`graph.py` 的 staged 分支须显式选择新旧准备函数和持久化状态；不能把新字符串方案伪装成原版本7的完整 blueprint。正文模板的说明、私有计划序列化、输入容量计算及 draft 请求冻结须识别新表示，保持可逆和原始值。`refit` 继续要求全部选定来源及必要上下文，完整工作流实际值仍不变地绑定实际声明 ID。

实现后验证：新旧请求字节与恢复隔离；完整输入和未知调用身份；失败/截断响应不升级；完整工作流图节点和公开正文绑定；概念决策缺少正式状态时最终拒绝；整轮预算；实际新建运行配置及旧数据保全。离线通过后仅提交一个固定真实开发案例，再独立核对方案内容。不得把新小语法的成功等同为完整 Deep Research 通过。
