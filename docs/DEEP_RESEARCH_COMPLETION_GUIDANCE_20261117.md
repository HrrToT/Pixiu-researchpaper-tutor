## 2. 拖慢原因与纠正

1. **局部通过没有转化为整份成果可用。** 删除坏声明后，剩余答案有时无法回答原问题。以结论、必要分析、条件、引用和展示的完整交付为单位。
2. **内容问题逐渐变成字段和协议问题。** 每遇失败就加约束，扩大提示负担及兼容组合。程序负责来源身份、权限、预算、数值绑定和持久化；模型负责推理与表达。新增字段须解释现有结构为何不能表达。
3. **用真实调用调试确定性错误。** 先回放保存的失败输入、响应和真实仓储路径，修复后再付费验证。
4. **调用容量与时间容量脱节。** 剩余调用数充足不代表来得及审核。按实测阶段耗时和完整输入大小核算整轮，保留末段时间。
5. **固定题逐渐成为训练样本。** 调试材料归开发集；独立验收用新材料，失败后退出独立集，不改名继续计独立通过。
6. **重复回归、环境恢复与过期文档占用主线。** 离线诊断无需先恢复全部服务。稳定源码一次全量，未改源码复用；当前状态只维护版本、适用证据、未过门槛和下一动作。

## 3. 五个交付包

| 交付包 | 主要工作 | 退出条件 |
| --- | --- | --- |
| P0 失败基线与根因 | 保存D2阶段耗时、输入身份/大小、错误与缺失内容；D3未知单列。检查重复获取、表格报告者错配、无效审核、建议前提、修订准入 | 每个拟改点有输入/响应或源码依据，区分事实、假设和反证动作；先不追加真实调用 |
| P1 完整比较与关键路径 | 改善材料复用、完整生成、审核分组和修订调度；以现有比较路径为基础 | 失败回放和相邻检查通过；整轮容量及时间可行；冻结全量后一次新D2，得到完整、正确、可读比较 |
| P2 可执行实验方案 | 复用共享定义→科学审核→编译→整答检查→一次修订；隔离传输未知 | 真实方案覆盖共同起点、四组变量、预算、指标、主/交互效应和局限；整轮可完成。旧未知不改判 |
| P3 独立内容与真实产品闭环 | 按原设计第19节复用适用D1—D6/H1—H6证据，补未过项；真实成果打开、定位、追问、保存、编辑、找回、重开 | 原硬门槛和评分满足；真实检索/全文/内容与产品对应适用候选，模拟不计科学通过 |
| P4 发布与交接 | 最终冻结、受影响检查、装载、旧数据兼容、必要故障回退、运行说明、PR更新 | 验收矩阵与实际交付一致；全部硬门槛通过后才退出草稿，不自动合并 |

P1具体决策：

- 材料：复用身份匹配且可用的已获取正文/表格，只补问题缺口；缓存仍核对权限、版本和来源，不以旧摘要替代正文。
- 生成：统一组织用户所需比较结构，含机制、额外处理成本、单组数值例子、可比条件和建议；同一事实只生成一次，分清报告论文与表中方法行。
- 审核：评估小批独立目标审核，减少重复传输与串行开销；每项保留自身原文、独立判定和失败隔离。先验证容量与效果，不预设批量必然更好。
- 调度：已明确硬错误优先进入一次有界修订；评估是否避免对明显残缺稿先做低收益整答调用。发布仍必须通过事实和整答检查。
- 无效审核：区分未完成、格式无效和科学不通过；不把无效审核说明当作论文事实修改。
- 若整轮预算仍不可行，报告各阶段实测成本，再决定预算或模型路由取舍；不先靠延长期限、加调用数或更换模型掩盖结构问题，不静默删要求。

P2约束：D3-v7保持冻结及预留，不同题换名重放。HTTP观测只帮助区分未来接收阶段，不能恢复旧未知结果。用已存输入测真实大方案在生成、审核、修订时的容量，不能删科学字段挤入。若旧未知无法核实，明确原门槛及影响，不能用更容易案例替换。

P3约束：联网发现和全文读取须有真实获取证据。结果优先，来源和过程收束。前端并行任务按接口、文件归属和交付版本对接。不再加入旧项目导入、完整新手走查、独立Edge恢复。

## 4. 每轮执行纪律

- 开始写清用户结果、当前失败证据、根因假设、修改层次、反证检查。每轮一个主要问题，允许必要跨模块依赖。
- 验证顺序：保存响应回放→局部/相邻测试→真实节点与仓储的无网络集成→稳定候选全量→一次有界真实案例→独立验收。
- 连续两次同类真实修复未改善完整结果，停止第三次提示微调，审职责、证据、预算；不再请求“碰运气”。
- 测试验证不同风险，不堆实现镜像测试。时间准入用确定性时钟；真实内容由成果评审，二者不互代。
- 全量期间冻结受检源码。文档更新校验JSON、链接和差异，不重跑9397项；受影响生产代码先局部后稳定全量。
- 独立行为包相邻检查通过后commit，稳定集成再全量。明确文件提交，保留并行前端脏文件与私有历史材料，不批量清理。
- 契约版本仅在确有持久化/行为隔离要求时新增；不叠加为固定题通过的开关。新增前明确维护边界。
- 不再接Qoder，不为提速更换Agent框架，不扩新功能。开源组件仅在能替代已定位维护负担时引入，核对许可证与依赖成本。
- 已授权同范围验证直接推进；未知模型调用不自动重试。每例仍遵守现有18调用、10万Token、360秒边界。
