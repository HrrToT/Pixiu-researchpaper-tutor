# 事实与推广命题分开核查

目标是解决 D1-v33 中核查模型混淆“不蕴涵”与“命题为假”的问题。完整 DR0—DR5 及独立验收仍未完成，旧失败不自动升级。

## 新核查职责

新任务使用 `scopeExpressionReviewContractVersion=2`。只有与实际目标文字完全匹配、可由已保存表达式重新编译且唯一的范围表达式，才使用分开核查；普通声明或匹配失败仍走普通路径。

1. 原始声明的数值、来源身份及其他发布前硬检查保持。程序将每个已声明 observedSettings 投影为单独的事实目标，没有猜测新条件；引用权限保持原声明自身范围。
2. 这些目标继续使用普通事实、范围强度、结果归属及完整语义核查。内部目标 ID 按原声明与表达式确定，便于调用账本稳定复用；不会作为用户报告中的新结论发布。
3. notEstablished 单独送入证据蕴涵判断，询问所给引用能否建立具体命题，而不要求论文作者自己声明“没有验证”。逐项检查实际比较域、量词、否定与作者遗漏断言，以及自己的原文字段绑定。
4. 服务端只在全部观察事实通过、全部命题明确为 not_entailed 且自身绑定有效时汇总为通过。任何事实失败、来源缺失、已蕴涵、量词含糊、推理未决或格式不完整均不能通过。这不是将旧整句 failed 改成 passed。

新版本以这种分工替代范围表达式的整句语义任务；旧版本 1 保留原整句核查及审计，旧运行不迁移。最终回答完整性核查保持。

## 费用与失败边界

各事实与蕴涵请求均经原 TrackedLLMInvoker、原 verify/verify_repair 节点及预留池，受整轮调用数、Token、截止时间和未知状态约束。最多四个观察设置和两个命题，可能增加核查请求数；不扩大预算来保证成功。输入容量不足时不截断自身证据或发送残缺请求。

不绕过剩余时间准入，不自动重试未知或失败调用。请求标识与文字确定，已确认结果可由原账本复用。普通结论需要先得到核查机会，避免新增范围任务挤占其预算。
