# 按固定要求核查回答完整性

D1-v40 的完整性审核从片段自行生成“仅在某数据集验证”“其他数据集未验证”等必要项，既偏离真实材料，也将有限引用误变成论文缺席断言。它还单独生成子项、整体状态和缺口说明，出现子项全部 covered、整体 partial、缺口目标为空的矛盾。

新运行 `.315` 的 `requestCoverageContractVersion=1` 改变核查、比较、方向调研和研究切入类回答的完整性协议；实验方案维持原有独立检查。服务端由已冻结 completionCriteria 编译固定检查项；无完成标准的义务和原问题总范围保留完整原问题作为检查项。不会从论文片段生成新的交付要求，也不改写冻结计划。

模型只对每个固定 checkId 返回 covered／partial／missing、真实回答字段绑定及简短理由。它不能返回或改写 requirement、aspects、criteria、整体状态和 gapDetail。多条接受回答可共同绑定同一要求；模型漏绑不等同于答案缺少内容。程序由每项原始判定投影为既有完成标准／aspect 检查，并保守汇总整体状态及精确缺口 ID。任何未满足项仍阻断完整覆盖，不把失败、格式无效或未知改为通过。

完整性只检查“是否回应固定要求”，不会增加科学认可。它看到的是已有独立事实核查接受的声明；事实、表格、数值、来源、语义及范围规则保持。来源资料仍完整进入预算内输入，用于发现固定要求下真正遗漏的条件，不能定义新要求或以引用替代缺少的回答。原新手解释、字面交付维度和必要条件政策保留。

检查理由只保留作私有审计，不作为新增要求或论文事实送往修订。修订的 missingAspects 来自固定要求原文，gapDetail 由未满足 ID 生成。辅助研究可申请 notRequired，但原有原问题完整覆盖、其他必需义务、原问题摘录和接受回答绑定门槛仍须全部成立。原问题和 answer_requirement 不能豁免。

新协议由服务端冻结且不能改写。没有开关的旧研究继续使用原请求，旧响应不迁移。输入容量、完整引用上下文、整轮时间／调用／Token、预留及无自动重试边界不变；一次原有审核调用内完成，不新增审核轮次。

## 保存输入回放与测试边界

D1-v40 最后一份旧审核响应按新协议明确拒绝，没有将其 partial/invalid 改为通过。用原计划、已接受回答和原问题组装四项固定检查，模拟判定全部保持 partial，全部字段引用正确解析，缺口文字不再增加“其他数据集未验证”；原 payload 哈希不变。没有模型调用或生产写入，不能当作内容验收。证据为 `deep-research-evidence/request-coverage-D1-v40-replay-20261027.json`。

定向检查覆盖新增／遗漏／重复 ID、私自改要求、旧响应拒绝、联合字段绑定、无效回答引用、辅助豁免、服务端策略与旧任务。最初回放发现投影的整体绑定与子项复用了同一字典，引用解析时会重复处理；已改为独立深拷贝。暂停故障注入也同步新审核入口，未改生产暂停规则。新协议仍依赖模型作真实覆盖判断，固定清单本身不能证明判断正确，也不能证明冻结计划已完美拆分用户需求。

最终固定源码的 44 文件、724 项关联回归通过（pytest 55.86 秒，外部 60.015 秒），全部研究模块及选中测试的前后哈希一致。定向检查与之重叠，不相加。收据为 `deep-research-evidence/request-coverage-regression-20261027.json`。

本轮不追加真实验证。D1-v40 与完整 DR0—DR5、内容质量及独立验收状态保持未通过。
