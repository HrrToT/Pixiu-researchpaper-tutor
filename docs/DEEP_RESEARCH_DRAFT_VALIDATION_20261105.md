# 草稿结构冲突的逐条拒绝与既有修订

日期：2026-11-05。候选版本 `.393`，服务端契约 `draftValidationContractVersion=1`。

## 问题与行为

G1N-v3 在完整 JSON 内对同一条目同时填写非空正文和 scopeExpression，既有严格编译器拒绝整轮。不能直接删除其中一个字段：那会替模型选择一个判断，而且原稿还有独立的数值与来源错误。

新运行逐条调用原编译器。正常条目保持原编译行为；结构无效的条目按原ID保存两种原始表达，并记录 `invalid_scope_expression`。它不会作为事实候选送给初始审核；其拒绝项进入既有一次有界修订，之后继续原来的事实、范围、数值、来源和完整性检查。无需新增结构修订模型节点，不扩大18调用/10万Token/360秒预算。

冲突原稿不能先经压缩或新手措辞重写，以免冲突被隐藏。因此含隔离项的原稿跳过初始措辞处理，先审核与修订；修订仍受既有篇幅处理和最终审核约束。其他条目并非因此获批。

发布及恢复发布再次检查：原隔离ID必须与独立修订审核实际接受的替换条目精确一致，且不能仍是原始冲突条目。任何残留非空 scopeExpression 的未编译条目均不能发布。剔除条目后原完整性结论被失效，不能继续声称完整。

## 保持的边界

- 不修改历史运行，不把旧失败改判为部分或完成。
- 未启用契约的运行保留整轮拒绝；布尔、字符串和未知版本不启用。
- 服务端设置契约，持久化后值与类型不可变；前端请求不能切换。
- 重复、缺失或非对象的条目ID不能安全隔离，继续整轮拒绝。
- 原报告、隔离原稿、初始拒绝、修订正文和独立审核记录分开保存。
- 截断或整体非法JSON仍拒绝；没有自动重发、未知请求恢复或额外模型调用。
- 本机制不修复或证明G1N-v3的0.42错误、GOF来源归属错误。

## 证据

聚焦联测检查原编译器、逐条隔离、正常条目审核、既有修订、独立审核正负路径及契约不可变。实际G1N-v3保存草稿回放仅隔离c4，c1/c2/c3/c5仍需普通审核；即使模拟审核器错误接受全部条目，c4仍被强制拒绝，未独立审核的替换不能发布。回放0模型、0网络、0生产写入，原失败未改变。
