# 数据库备份恢复与读取兼容性演练

已将当前服务加载前的一致性备份恢复到项目内全新隔离目录，验证备份可读及旧Java构建的读取兼容性。没有替换当前服务、原数据库或原始备份，没有执行模型请求或恢复历史研究。

## 恢复方式

- 复制关闭后校验过的H2备份到唯一测试目录，源/目标摘要一致。
- 从现有Docker持久卷只复制研究SQLite备份；恢复副本摘要与已记录的一致性备份摘要相同，完整性检查通过。
- Java使用加载修复之前的JAR，SHA-256 `3ac7559375c93118fd6a006112e1c2d2db29b1b954bc996d5ded964c3b3c90b0`，仅监听127.0.0.1:8186，使用复制的H2。
- Python继续使用当前固定执行器及已保存的运行契约，新入口关闭，仅监听127.0.0.1:8195；研究工作线程与发布队列派送禁止执行，所有HTTP仅允许两个隔离端口。
- 不将新版运行交给旧执行引擎，也不通过恢复或继续操作处理未决请求。

## 复现与边界

可复用入口是 `scripts/verify-research-backup-restore.py`。需要运行中的现有Docker容器提供已记录备份、原H2备份文件、匹配的基线证明、Java及项目JAR；每次提供唯一run-id。脚本拒绝已有目录或占用端口，始终复制备份到新目录。

```powershell
.venv-refactor/Scripts/python.exe -X utf8 scripts/verify-research-backup-restore.py --java <java.exe路径> --jar <回退JAR路径> --h2-backup <H2备份路径> --baseline docs/deep-research-evidence/service-fixes-loaded-20261112.json --run-id <唯一标识>
```

失败及成功证明分别是 `deep-research-evidence/backup-restore-verified-20261112.json`、`deep-research-evidence/backup-restore-streamed-20261112.json`。副本、SQLite与Java日志在对应tmp目录，不纳入Git。

本轮是备份恢复/读取兼容性证明，不是当前生产环境故障切换、索引灾难恢复或真实内容质量验收。旧Java构建缺少近期成果保护，不能仅因可读就作为推荐的日常运行版本。当前回退策略仍以关闭新入口、保留固定执行器与旧报告读取为主，涉及二进制降级时仍须单独核对写入保护及接口兼容性。
